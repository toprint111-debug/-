# 交付约定

这是便于查用与维护的最小约定，不限定章节、节点数、层数或格式。局部样例明确范围；未覆盖部分不能算遗漏已解决。

## 可读内容

- 书籍与阅读范围：版本标识、已读和未核范围、图表/注释、缺损与疑点。
- 整理决策：作者主线与具体理由；沿用、局部整理或重组；原结构到学习入口的对应。
- 学习结构：主要回答、核心及其他方法、重要关系。方法说明适用问题、操作、直接产出、条件；区分原书与改编。
- 双向核查与状态：哪些原文对应哪些入口、哪些省略及原因；结构自查、独立复核、跨书与效果验证分别记录。

## 供页面或练习关联的数据

可采用 JSON，也可用等价表格。节点 ID 在同一次交付内唯一；实质改义时记录版本变化。导航关系不冒充书中因果或执行关系。

```json
{
  "version": "交付版本",
  "source": {"title": "书名", "file_sha256": "源文件摘要"},
  "scope": {"delivery": "整本或明确局部", "reading_record": "实际记录入口"},
  "nodes": [{
    "id": "稳定标识",
    "claim": "有内容的主张或方法",
    "kind": "概念/方法/导航等",
    "provenance": "原书明确/整理归纳/项目改编/待核实",
    "refs": [{
      "anchor": "章节与段落标识",
      "location": "EPUB内部路径或其他可定位位置",
      "role": "direct/condition/counterexample/case",
      "supports": "原文支持或限制什么",
      "applies_to": "条件限定的具体主张或分支"
    }],
    "exercise": {"status": "未设计", "target": null}
  }],
  "relations": [{
    "from": "节点ID", "to": "节点ID",
    "type": "包含/并列/依赖/反馈等",
    "provenance": "原书明确或整理归纳等",
    "explanation": "这一关系具体意味着什么",
    "refs": [{"anchor": "关系依据", "supports": "支持这一关系的具体用途"}]
  }],
  "reverse_coverage": [{"source_item": "重要原文或主要部分", "destination": "节点/学习入口或省略理由"}]
}
```

`applies_to` 对重要条件必需，可用同等清楚文字表达；无需给每个普通引用加此字段。位置、锚点和源版本组合要足以回查。若引用另存摘录文件，附文件与实际存在的锚点；有条件时增加段落摘要检查失配。摘要一致只能检查定位，不能证明语义正确。

练习关联只有在实际存在时才填写入口；状态分开写“未设计”“已设计未验证”“已核对应”“已试用”等，不用单一完成标记代替。
