# 后续维护计划

这是后续计划，不是已实现功能或审批门槛。

## 第一阶段：让现有 Skill 能被他人理解和试用

- 首版提供已有 Skill、原创演示和说明，采用 MIT 许可。
- 用原创模拟材料检查使用说明是否清楚。
- 根据真实反馈修正规则与示例，保留改变原因。

## 第二阶段：整理通用程序

- 从本地样例中分离书籍数据和可复用代码。
- 实现可核对的 EPUB 提取、段落定位与导入检查。
- 用同一数据约定生成可离线打开的结构、原文与练习页面。
- 以用户自带文件运行，公开仓库使用原创或授权示例。

## 第三阶段：验证学习过程

- 用不同结构的方法书逐书核查，记录失败与修订。
- 改进方法讲解、集中反馈和练习交接。
- 分开记录获得帮助、新任务、真实使用和保持情况。

## 日常怎样维护

用户通过 Issue 提出问题。维护者先复现和判断范围，再做改动，在提交或 PR 中解释原因和验证情况；有一组值得发布的变化时更新版本及 CHANGELOG。

实际发生过什么就记录什么。没有反馈时不编造 Issue，没有自动检查时不宣称 CI 通过，不以提交次数或 Stars 的增长替代产品价值。
